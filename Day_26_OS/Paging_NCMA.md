# Day 26/30 — Paging: Non-Contiguous Memory Allocation

Day 25 showed that compaction can fix external fragmentation, but it costs time, and free holes still have to be found and fitted. Today's lecture asks a better question: why must a process occupy one contiguous block at all? **Paging** breaks both logical and physical memory into fixed-size pieces, so a process can live in any free frames, scattered wherever they happen to be. The price is slower address translation, and the fix for that is the **Translation Look-aside Buffer (TLB)**.

---

## 1. The Problem with Dynamic Partitioning

- The main disadvantage of dynamic partitioning is **external fragmentation**.
- It can be removed by **compaction**, but compaction has overhead.
- So the notes call for a more **dynamic, flexible, or optimal** mechanism to load processes into partitions.

---

## 2. The Idea Behind Paging

Imagine two free holes of **1 KB** each in memory, and a process that needs **2 KB**.
- With contiguous allocation, this fails. The two holes add up to 2 KB, but they aren't contiguous.
- **Fix:** divide the process into **1 KB blocks**. Each block can go into a different hole.

Paging applies this idea systematically.

---

## 3. Paging: Definition and Core Terms

> **Paging** is a memory-management scheme that lets the physical address space of a process be **non-contiguous**.

- It **avoids external fragmentation**, so compaction is no longer needed.
- **Frames:** physical memory is divided into fixed-size blocks called **frames**.
- **Pages:** logical memory (the process) is divided into blocks of the same size, called **pages**.
- **Page size = frame size.** Every page fits exactly in one frame.

### Choosing the Page Size

- The page size is usually set by the **processor architecture**.
- Traditionally, all pages in a system had a uniform size, such as **4,096 bytes (4 KB)**.
- Modern processors often support **two or more page sizes** at the same time, because each size has benefits.

### The Page Table

- The **page table** is a data structure that stores which **page** is mapped to which **frame**.
- It holds the **base address** of each page in physical memory.
- Each process has its own page table.
- The page table is stored in **main memory** when the process is created, and its base address is stored in the **Process Control Block (PCB)**.
- The system has a **page-table base register (PTBR)** that points to the current page table. On a context switch, the OS only has to change this one register to switch page tables.

---

## 4. Address Translation

Every logical address generated by the CPU is split into two parts:

- **Page number (p):** used as an **index** into the page table, to find the base address of the frame that holds the page.
- **Page offset (d):** the position of the byte inside that page.

```
Logical address = [ page number p | offset d ]
                         │             │
                         ▼             │
                 page table[p] → frame f
                                       │
Physical address = [ frame f | offset d ]
```

The offset is the same in the logical and physical address, because a page and its frame are the same size.

### Worked Example from the Diagram

The notes show a process P1 with four pages, and this page table:

| Page | Frame |
|---|---|
| 0 | 1 |
| 1 | 4 |
| 2 | 3 |
| 3 | 7 |

Page 0 sits in frame 1, page 1 in frame 4, page 2 in frame 3, and page 3 in frame 7. The four pages are **not** next to each other in physical memory, but the process runs correctly. That is the point of paging.

### Offset Bits (Extra Note, Not in the Notes)

If the page size is **2^k** bytes, the offset needs **k bits**. For example, with a 4,096-byte (2^12) page, the offset is **12 bits**, and the leading bits of the logical address are the page number. The handwritten page in your notes shows this split, with the page number in the leading bits and the offset in the trailing bits.

---

## 5. How Paging Avoids External Fragmentation

- Pages of a process can be allocated to **any random free frames** in physical memory.
- A free frame never has to be large enough for the whole process. It only has to be large enough for one page, and every frame has the same size.
- So no leftover holes are too small to use.
- Some **internal** fragmentation remains. The last page of a process may be partly empty.

---

## 6. Why Paging Is Slow, and How We Make It Fast

- The problem: the page table lives in **main memory**. Every memory access then takes **two** trips. One trip reads the page table to find the frame, and a second trip reads the desired location.
- The fix: **the Translation Look-aside Buffer (TLB)**.

### The TLB

- A **hardware cache**, meaning high-speed memory built into the processor.
- Holds **key–value** pairs: key is the **page number**, value is the **frame number**.
- **Operation:**
  1. The page number is looked up in the TLB.
  2. **TLB hit:** the TLB has the mapping, so the frame is found immediately, and the physical address is formed as frame + offset.
  3. **TLB miss:** the page table in main memory is used. After getting the frame, the system puts the new entry into the TLB, so the next access to that page is fast.

### ASIDs: Protecting Multiple Processes in the TLB

- Each TLB entry stores an **Address Space Identifier (ASID)**.
- An ASID uniquely identifies a process. It provides **address-space protection**, and it allows the TLB to hold entries for **several processes at once**.
- When the TLB looks up a page, it checks that the ASID matches the currently running process.
- If the ASID doesn't match, the lookup is treated as a **TLB miss**. This means one process can never use another process's mapping.

---

## 7. Summary of Contiguous vs Paging

| | Contiguous (Day 24–25) | Paging (Day 26) |
|---|---|---|
| Process in memory | One contiguous block | Pages in any free frames |
| External fragmentation | Yes | No |
| Internal fragmentation | Yes (fixed partitions) | Only in the last page |
| Compaction needed | Often | No |
| Address translation | Base + limit registers | Page table (sped up by TLB) |

---

## Key Takeaways

- **Paging** lets a process's physical memory be **non-contiguous**. It avoids external fragmentation and makes compaction unnecessary.
- Physical memory is split into **frames**, logical memory into **pages**, and both have the same size.
- A logical address is **page number + offset**. The page number indexes the **page table** to find the frame.
- The page table lives in **main memory**, and its base is in the **PCB**. The **PTBR** changes page tables on a context switch.
- Translation is **slow** because it needs extra memory references. The **TLB** is a hardware cache of page-to-frame mappings that makes repeated accesses fast.
- **ASIDs** let the TLB hold entries for several processes safely.
