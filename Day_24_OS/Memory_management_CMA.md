## 1. Multiprogramming and Shared Memory

1. In a multiprogramming environment, we have multiple processes in main memory (the **ready queue**) to keep **CPU utilization high** and to make the computer **responsive** to users.
2. To realize this increase in performance, we must keep several processes in memory. That is, we must **share** main memory. As a result, we must **manage** main memory for all the different processes.

```
Multiprogramming → many processes in RAM
Use case of logical and physical addresses → provide isolation and memory protection
```

---

## 2. Logical versus Physical Address Space

### a. Logical Address

- An address **generated by the CPU**.
- The logical address is basically the address of an instruction or data used by a process.
- The user can access the logical address of the process.
- The user has **indirect** access to the physical address through the logical address.
- A logical address does not exist physically. Hence, it is also called a **virtual address**.
- The set of all logical addresses generated by any program is referred to as the **Logical Address Space**.
- **Range: 0 to max.**

### b. Physical Address

- An address **loaded into the memory-address register** of the physical memory.
- The user can **never** access the physical address of the program.
- The physical address is in the memory unit. It is a location in the main memory, physically.
- A physical address can be accessed by a user **indirectly but not directly**.
- The set of all physical addresses corresponding to the logical addresses is commonly known as the **Physical Address Space**.
- It is computed by the **Memory Management Unit (MMU)**.
- **Range: (R + 0) to (R + max), for a base value R.**

### c. The runtime mapping from virtual to physical address is done by a hardware device called the **memory-management unit (MMU)**.

### d. The user's program mainly generates the logical address, and the user thinks that the program is running in this logical address. But the program mainly needs physical memory in order to complete its execution.

### e. Diagram: relocation register

## 3. How the OS Manages Isolation and Protection (Memory Mapping and Protection)

a. The OS provides this **Virtual Address Space (VAS)** concept.

b. To separate memory space, we need the ability to determine the range of legal addresses that the process may access, and to ensure that the process can access only these legal addresses.

c. The **relocation register** contains the value of the smallest **physical address** (base address R). The **limit register** contains the range of logical addresses. For example: **relocation = 100040** and **limit = 74600**.

d. **Each logical address must be less than the limit register.**

e. The MMU maps the logical address **dynamically** by adding the value in the relocation register.

f. When the CPU scheduler selects a process for execution, the **dispatcher** loads the relocation and limit registers with the correct values as part of the **context switch**. Since every address generated by the CPU (logical address) is checked against these registers, we can protect both the OS and other users' programs and data from being modified by a running process.

g. Any attempt by a program executing in **user mode** to access the OS memory or other users' memory results in a **trap** to the OS, which treats the attempt as a **fatal error**.

h. **Address Translation**

```
                Limit Register          Relocation
                                         Register

   CPU ──Logical──► ( < ) ──Yes──────► ( + ) ──Physical──► Main Memory
        address       │                     Address

```

## 5. Contiguous Memory Allocation

a. In this scheme, **each process is contained in a single contiguous block of memory**.

### b. Fixed Partitioning

i. The main memory is divided into **partitions of equal or different sizes**.

```
   Operating System  ← partition for OS
  ┌────────────────┐
  │ 3 MB  Process P1 │ partition 1   (3 MB process, 1 MB wasted)
  │ 1 MB           │
  ├────────────────┤
  │ 3 MB  Process P2 │ partition 2
  │ 1 MB           │
  ├────────────────┤
  │ 3 MB  Process P3 │ partition 3
  │ 1 MB           │
  ├────────────────┤
  │ 3 MB  Process P4 │ partition 4
  │ 1 MB           │
  └────────────────┘
        ↑ 1 MB inside each partition = internal fragmentation

   Unused space: 1 MB × 4 = 4 MB, in separate pieces
   Process P5 (4 MB) → cannot be executed, even though there is 4 MB
                       space available, but not contiguous.
```

ii. *(Diagram continued in the notes.)*

iii. **Limitations:**

1. **Internal Fragmentation:** if the size of the process is less than the total size of the partition, some size of the partition gets wasted and remains unused. This is wastage of memory, and it is called **internal fragmentation**.

2. **External Fragmentation:** the total unused space of various partitions cannot be used to load the processes, even though there is space available but not in contiguous form.

3. **Limitation on process size:** if the process size is larger than the size of the maximum-sized partition, then that process cannot be loaded into memory. Therefore, a limitation can be imposed on the process size: it cannot be larger than the size of the largest partition.

4. **Low degree of multiprogramming:** in fixed partitioning, the degree of multiprogramming is fixed and very low, because the size of the partition cannot be varied according to the size of processes.

---

### c. Dynamic Partitioning

i. In this technique, **the partition size is not declared initially**. It is declared **at the time of process loading**.

```
   Operating System  ← partition for OS
  ┌────────────────┐
  │ Process P1 (5 MB) │ partition 1
  ├────────────────┤
  │ Process P2 (2 MB) │ partition 2
  ├────────────────┤
  │ Process P3 (3 MB) │ partition 3
  ├────────────────┤
  │ Process P4 (4 MB) │ partition 4
  └────────────────┘

   Dynamic Partitioning (Process Size = Partition Size)
```

ii. *(Diagram continued in the notes.)*

iii. **Advantages over fixed partitioning**

1. **No internal fragmentation.** A partition is created to exactly the size of the process that comes in.
2. **No limit on size of process.**
3. **Better degree of multiprogramming.**

iv. **Limitation**

1. **External fragmentation**

```
   Operating System  ← partition for OS
  ┌────────────────┐
  │ 5 MB Free      │ partition 1
  ├────────────────┤
  │ Process P2 (2 MB) │ partition 2
  ├────────────────┤
  │ 3 MB Free      │ partition 3
  ├────────────────┤
  │ Process P4 (4 MB) │ partition 4
  └────────────────┘

   Process P1 → Completed
   Process P3 → Completed
   Process P5 (8 MB) → cannot be loaded into memory, even though there is
                       8 MB space available, but not contiguous.

   External Fragmentation in Dynamic Partitioning
```

**Handwritten example:** a 3 MB process P6 is loaded into the 5 MB free hole. It takes exactly 3 MB, and the leftover becomes a different partition (a new hole). So it is not internal fragmentation, because the partition is made to the size of the incoming process.

## 6. Comparison

| | Fixed Partitioning | Dynamic Partitioning |
|---|---|---|
| Partition size | Declared initially, equal or different | Declared at process loading |
| Internal fragmentation | Yes | No |
| External fragmentation | Yes | Yes |
| Limit on process size | Yes (largest partition) | No |
| Degree of multiprogramming | Fixed and low | Better |

---

## Key Takeaways

- Multiprogramming keeps several processes in memory, so main memory must be **shared** and **managed**.
- **Logical addresses** are generated by the CPU and are virtual. **Physical addresses** are real memory locations, computed by the **MMU**.
- The **relocation register** gives the base physical address. The **limit register** bounds the logical addresses. Every logical address must be less than the limit.
- The **dispatcher** loads these registers during each context switch. Any user-mode access outside the legal range traps as a fatal error.
- **Contiguous allocation** puts each process in one block. **Fixed partitioning** causes internal and external fragmentation and limits process size. **Dynamic partitioning** removes internal fragmentation but still has external fragmentation.
